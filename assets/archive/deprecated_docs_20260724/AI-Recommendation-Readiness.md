# AI 荐股所需能力与当前就绪度

## 结论

当前项目已经具备“候选股票排序 + 单股证据解释 + 历史复盘”的研究原型，但还不应把 AI 直接作为荐股决策器。更可靠的结构是：量化规则产生候选，数据质量门禁筛除异常，Codex 只负责归纳证据、指出冲突和生成可审计说明，最终结果继续接受后验检验和人工确认。

## 需要的背景知识

1. 市场制度：A 股 T+1、涨跌停、停牌、ST、除权除息、交易费用和不同板块规则。
2. 量化研究：因子有效性、样本外验证、数据泄漏、幸存者偏差、过拟合、容量与交易成本。
3. 基本面研究：财务三表、盈利质量、现金流、估值、行业周期和公司治理。
4. 技术与资金：趋势、波动率、成交量、换手率、资金流、筹码与关键价位。
5. 事件研究：公告、业绩预告、监管信息、产业链价格、政策和宏观变量的发布时间边界。
6. 风险管理：组合相关性、仓位上限、回撤、流动性、黑天鹅和模型失效条件。

## 数据源与当前能力

| 数据/能力 | 荐股用途 | 当前可提供 | 当前状态 |
|---|---|---:|---|
| 日 K、成交量、成交额 | 趋势、波动、流动性、技术因子 | 是 | TickFlow 已接入；现有 JSON 有历史 K 线 |
| 实时行情 | 盘中状态、价格偏离、成交变化 | 部分 | 有 TickFlow Key 时可取快照；分钟数据仍有旧源兼容路径 |
| 技术因子 | RSI、MACD、ATR、均线等候选评分 | 是 | `factors/` 已生成并有质量门禁 |
| 市场环境 | 指数、涨跌分布、资金环境 | 是 | `latest.json` 与指数基准可进入诊股上下文 |
| 财务与估值 | 盈利质量、估值安全边际 | 部分 | `enhance/` 有估值/公司行为等数据，但覆盖度和时效需逐标的检查 |
| 舆情 | 热度、观点变化、风险线索 | 部分 | `sentiment/` 已有接口；来源稳定性和噪声控制仍有限 |
| 公告与监管事件 | 识别业绩、处罚、减持、重组等催化/风险 | 部分 | `impact/` 可承载部分事件，尚缺权威公告全文与统一发布时间字段 |
| 行业与产业链 | 行业景气、上下游价格、相对强弱 | 部分 | 有行业/材料价格扩展思路，尚未形成稳定全市场截面 |
| 预测与候选排序 | 从股票池筛出待研究标的 | 是 | `predictions/`、`selector/`、`recommendations/` 已有产物 |
| 回测和后验复盘 | 证明策略在历史与样本外有效 | 是 | `backtest/`、`review/`、`replay/` 已有，但当前股票池很小 |
| 组合风险 | 防止单股结论叠加后风险失控 | 是 | `portfolio/`、`decision/` 已有基础约束 |
| 全市场点时股票池 | 避免只在小样本内“挑赢家” | 是 | 使用 TickFlow Universe，并保留日期快照 |
| 点时财务/公告数据库 | 严格避免使用当时尚未发布的信息 | 否 | 需要所有字段携带 `published_at/known_at` 并做截面快照 |
| 实盘成交与滑点反馈 | 校准可交易性和实际收益 | 否 | 当前只有模拟交易，不足以证明真实执行效果 |

## 从现在到可用荐股系统的最短路径

1. 先扩展为“全市场、点时可重建”的股票池，并保存退市/ST/停牌历史。
2. 统一所有证据的 `source`、`published_at`、`known_at`、`as_of` 和质量评分。
3. 用横截面 walk-forward 验证 selector；训练期、验证期、最终测试期严格隔离。
4. 把交易成本、涨跌停不可成交、T+1、停牌和容量约束纳入回测。
5. AI 只读取冻结的 Evidence Package，输出结构化理由、反证、失效条件和缺失数据，不直接自由生成股票代码。
6. 建立推荐记录：候选时间、当时证据、模型版本、1/5/20 日收益、最大不利波动和是否可成交。
7. 达到预先设定的样本量、稳定性和回撤门槛后，再以小规模模拟盘/影子盘验证。

## 当前可以安全上线的形态

- “AI 研究候选”：selector 给出候选，AI 解释支持与反对证据。
- “AI 诊股”：用户指定股票后生成上下文约束的研究报告。
- “AI 风险复核”：在已有量化建议上查找证据冲突、数据过期和失效条件。

暂不建议上线“AI 自动荐股/自动下单”。当前最关键的缺口不是模型，而是全市场点时数据、样本外证据和真实可交易性反馈。
